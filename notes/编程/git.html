Git 版本控制手册

18 条
分布式版本控制常用命令速查：仓库、提交、分支、合并、远程、撤销与排错。
1 初始化 / 克隆
git init # 在当前目录建立仓库 git clone <url> # 克隆远程仓库 git clone <url> dir # 克隆到指定目录 git clone --depth 1 <url> # 浅克隆（只取最新提交）
2 身份与全局配置
git config --global user.name "你的名字" git config --global user.email "you@mail.com" git config --global core.editor "code --wait" git config --list # 查看所有配置
3 常用别名
git config --global alias.st status git config --global alias.co checkout git config --global alias.br branch git config --global alias.lg "log --oneline --graph --all"
4 查看状态与差异
git status # 工作区/暂存区状态 git diff # 工作区 vs 暂存区 git diff --staged # 暂存区 vs 上次提交 git diff HEAD~1 # 与上一版本比较
5 暂存与提交
git add file.txt # 添加指定文件 git add . # 添加全部改动 git add -p # 交互式逐块添加 git commit -m "信息" git commit -am "信息" # 跟踪文件的改动直接提交
6 修改上一次提交
git commit --amend -m "新信息" # 改提交信息/追加改动 # 注意：已 push 的提交不要 amend
7 .gitignore
# 忽略规则，一行一个 *.log # 所有 .log build/ # build 目录 !keep.log # 例外：不忽略 /root_only # 仅根目录
8 分支操作
git branch # 列出本地分支 git branch -a # 含远程分支 git switch -c dev # 新建并切换（等价 checkout -b） git switch main # 切换分支 git branch -d dev # 删除已合并分支 git branch -D dev # 强制删除
9 合并 merge
git switch main git merge dev # 把 dev 合并进 main git merge --no-ff dev # 保留合并提交节点 git merge --abort # 冲突时放弃合并
10 变基 rebase
git switch dev git rebase main # 把 dev 接到 main 最新处 # 优点：历史线性；缺点：改写提交 # 黄金法则：不要 rebase 已共享(push)的提交
11 解决冲突
# 冲突文件中出现标记： <<<<<<< HEAD 本分支内容 ======= 对方分支内容 >>>>>>> dev # 手动编辑后： git add 冲突文件 git commit # 或 git rebase --continue
12 远程仓库
git remote -v # 查看远程 git remote add origin <url> # 添加远程 git remote set-url origin <url> # 修改地址
13 拉取与推送
git fetch # 只下载不合并 git pull # fetch + merge git pull --rebase # fetch + rebase（历史更干净） git push origin main git push -u origin dev # 首次推送并建立跟踪 git push --tags # 推送标签
14 标签 tag
git tag # 列出标签 git tag v1.0 # 轻量标签 git tag -a v1.0 -m "发布" # 附注标签 git push origin v1.0
15 撤销工作区改动
git restore file.txt # 丢弃工作区改动（新语法） git restore --staged file # 取消暂存（保留改动） git checkout -- file # 旧语法，同上丢弃
16 回退提交
git reset --soft HEAD~1 # 撤销提交，改动留暂存区 git reset --mixed HEAD~1 # 撤销提交+取消暂存（默认） git reset --hard HEAD~1 # 彻底丢弃提交与改动（危险） git revert <commit> # 生成反向提交（安全，不改写历史）
17 查历史 / 找回
git log --oneline --graph git log -p file.txt # 某文件的改动历史 git blame file.txt # 每行由谁最后修改 git reflog # 引用日志，找回丢失的提交 git reset --hard <reflog里的哈希>
18 暂存现场 stash
git stash # 暂存当前改动 git stash list # 查看栈 git stash pop # 恢复并弹出 git stash apply # 恢复但保留 git stash drop # 丢弃
