设计模式学习笔记 (C++)

30 条
GoF 23 种设计模式 + SOLID 原则，每种配最简洁的 C++ 代码辅助理解。分创建型、结构型、行为型三类。
1 单一职责 SRP
一个类只负责一件事，只有一个引起它变化的原因。 // 拆分：数据存储、格式化、打印各自成类，而非塞进一个 God 类。
2 开闭原则 OCP
对扩展开放、对修改关闭。用抽象/多态新增行为，而非改旧代码。 struct Shape { virtual double area() const = 0; }; // 新增形状只需派生，不改已有代码。
3 里氏替换 LSP
子类对象可替换父类而不破坏正确性。派生类不削弱前置条件、不违背基类契约。
4 接口隔离 ISP
不强迫客户依赖它不用的接口。宁可多个小接口，不要一个胖接口。
5 依赖倒置 DIP
高层与低层都依赖抽象，而非具体实现。 class Engine { public: virtual void start()=0; }; class Car { Engine& e; public: Car(Engine& e):e(e){} }; // 注入抽象
6 单例 Singleton
保证一个类只有一个实例并提供全局访问点。 class Log { public: static Log& inst(){ static Log s; return s; } // C++11 线程安全 void write(const std::string& m){ /* ... */ } private: Log() = default; Log(const Log&) = delete; Log& operator=(const Log&) = delete; };
7 工厂方法 Factory Method
定义创建接口，由子类决定实例化哪个类。 struct Product { virtual ~Product()=default; virtual void use()=0; }; struct A : Product { void use() override {} }; struct Creator { virtual std::unique_ptr<Product> create()=0; }; struct CreatorA : Creator { std::unique_ptr<Product> create() override { return std::make_unique<A>(); } };
8 抽象工厂 Abstract Factory
创建一系列相关产品，而不指定具体类。 struct Button{virtual ~Button()=default;}; struct CheckBox{virtual ~CheckBox()=default;}; struct GUIFactory { virtual std::unique_ptr<Button> button()=0; virtual std::unique_ptr<CheckBox> check()=0; }; // WinFactory / MacFactory 分别产出成套控件
9 建造者 Builder
分步构造复杂对象，同一构造过程生成不同表示。 struct Pizza { std::string dough, sauce; }; class Builder { Pizza p; public: Builder& dough(std::string d){ p.dough=std::move(d); return *this; } Builder& sauce(std::string s){ p.sauce=std::move(s); return *this; } Pizza build(){ return p; } }; // auto pz = Builder().dough("thin").sauce("tomato").build();
10 原型 Prototype
通过克隆已有对象创建新对象。 struct Shape { virtual ~Shape()=default; virtual std::unique_ptr<Shape> clone() const = 0; }; struct Circle : Shape { int r; std::unique_ptr<Shape> clone() const override { return std::make_unique<Circle>(*this); } };
11 适配器 Adapter
把一个接口转换成客户期望的另一个接口。 struct Target { virtual void request()=0; }; struct Adaptee { void specific(){} }; struct Adapter : Target { Adaptee a; void request() override { a.specific(); } // 转接 };
12 桥接 Bridge
抽象与实现分离，各自独立变化。 struct Device { virtual void on()=0; virtual ~Device()=default; }; struct TV : Device { void on() override {} }; struct Remote { // 抽象持有实现指针 Device& d; Remote(Device& d):d(d){} void power(){ d.on(); } };
13 组合 Composite
把对象组成树形结构，统一处理叶子与容器。 struct Node { virtual int size()=0; virtual ~Node()=default; }; struct File : Node { int size() override { return 1; } }; struct Dir : Node { std::vector<std::unique_ptr<Node>> kids; int size() override { int s=0; for(auto& k:kids) s+=k->size(); return s; } };
14 装饰器 Decorator
动态给对象叠加职责，替代继承扩展。 struct Coffee { virtual int cost()=0; virtual ~Coffee()=default; }; struct Base : Coffee { int cost() override { return 5; } }; struct Milk : Coffee { std::unique_ptr<Coffee> c; Milk(std::unique_ptr<Coffee> c):c(std::move(c)){} int cost() override { return c->cost()+2; } };
15 外观 Facade
为子系统提供一个统一的高层接口。 struct CPU{void run(){}}; struct Disk{void load(){}}; class Computer { // 外观封装复杂子系统 CPU cpu; Disk disk; public: void start(){ disk.load(); cpu.run(); } };
16 享元 Flyweight
共享细粒度对象，节省内存(内蕴状态共享，外蕴状态传入)。 struct Glyph { char c; }; // 内蕴状态 std::map<char,Glyph> pool; Glyph& get(char c){ return pool.emplace(c,Glyph{c}).first->second; }
17 代理 Proxy
为对象提供替身以控制访问(远程/虚拟/保护/缓存)。 struct Image { virtual void draw()=0; virtual ~Image()=default; }; struct Real : Image { Real(){/*重加载*/} void draw() override {} }; struct Proxy : Image { // 延迟加载 std::unique_ptr<Real> real; void draw() override { if(!real) real=std::make_unique<Real>(); real->draw(); } };
18 策略 Strategy
封装可互换的算法，运行时切换。 struct Sort { virtual void run()=0; virtual ~Sort()=default; }; struct Quick : Sort { void run() override {} }; struct Ctx { // 持有策略 Sort* s; void exec(){ s->run(); } };
19 观察者 Observer
一对多依赖，主题变化时自动通知观察者。 struct Obs { virtual void update(int)=0; virtual ~Obs()=default; }; struct Subject { std::vector<Obs*> obs; void attach(Obs* o){ obs.push_back(o); } void notify(int v){ for(auto* o:obs) o->update(v); } };
20 命令 Command
把请求封装成对象，支持排队、撤销、日志。 struct Cmd { virtual void exec()=0; virtual ~Cmd()=default; }; struct Light { void on(){} }; struct OnCmd : Cmd { Light& l; OnCmd(Light& l):l(l){} void exec() override { l.on(); } }; // Invoker 持有 Cmd 列表依次 exec
21 状态 State
对象内部状态改变时改变其行为(消除大量 if/switch)。 struct State { virtual void handle()=0; virtual ~State()=default; }; struct On : State { void handle() override {} }; struct Machine { State* st; void request(){ st->handle(); } // 行为随状态变化 };
22 模板方法 Template Method
父类定义算法骨架，子类重写某些步骤。 struct Game { void play(){ init(); start(); end(); } // 骨架固定 virtual void init()=0; virtual void start()=0; virtual void end(){} virtual ~Game()=default; };
23 迭代器 Iterator
顺序访问聚合元素而不暴露内部结构。 template<class T> struct Vec { std::vector<T> d; auto begin(){ return d.begin(); } auto end(){ return d.end(); } // 复用 STL 迭代器 }; // for(auto& x : vec) ...
24 中介者 Mediator
用中介对象封装一组对象的交互，降低耦合。 struct Mediator { virtual void notify(const std::string&)=0; }; struct Component { Mediator* m; void changed(){ m->notify("ev"); } // 不直接引用其它组件 };
25 职责链 Chain of Responsibility
请求沿处理者链传递，直到被处理。 struct Handler { Handler* next=nullptr; virtual bool can(int)=0; void handle(int r){ if(can(r)){/*处理*/} else if(next) next->handle(r); } virtual ~Handler()=default; };
26 访问者 Visitor
在不改元素类的前提下定义作用于其上的新操作(双分派)。 struct Circle; struct Square; struct Visitor { virtual void visit(Circle&)=0; virtual void visit(Square&)=0; }; struct Shape { virtual void accept(Visitor&)=0; virtual ~Shape()=default; }; struct Circle : Shape { void accept(Visitor& v) override { v.visit(*this); } };
27 备忘录 Memento
在不破坏封装的前提下保存/恢复对象状态。 struct Memento { int state; }; struct Originator { int state=0; Memento save(){ return {state}; } void restore(const Memento& m){ state=m.state; } };
28 解释器 Interpreter
为语言定义文法并解释其中的句子。 struct Expr { virtual int eval()=0; virtual ~Expr()=default; }; struct Num : Expr { int v; int eval() override { return v; } }; struct Add : Expr { Expr* l; Expr* r; int eval() override { return l->eval()+r->eval(); } };
29 如何选择
先满足 SOLID 与 KISS，模式是为解决具体问题而用，切忌为用而用(过度设计)。 创建型:解耦对象创建;结构型:组织类与对象;行为型:分配职责与交互。
30 现代 C++ 提示
多用 std::unique_ptr/shared_ptr 管理所有权; 用 std::function/lambda 可替代部分策略/命令模式; 模板与 CRTP 可实现编译期多态(静态策略),避免虚函数开销。
