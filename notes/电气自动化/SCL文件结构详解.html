IEC 61850 SCL 文件结构详解

22 条
基于《61850模型说明》整理。SCL(变电站配置描述语言, IEC 61850-6) 基于 XML，用于描述 IED 模型、通信参数与变电站结构。含 ICD/SSD/SCD/CID 等文件类型。
1 SCL 是什么
SCL = Substation Configuration description Language(IEC 61850-6)，基于 XML。 用面向对象方式对变电站、IED 设备、通信系统统一建模，实现装置能力的自我描述与工具间互操作。 遵循 XML 1.0 语法，用 XML Schema(SCL.xsd 等 8 个 xsd) 校验结构。
2 四种模型文件
ICD (IED Capability Description)：厂家提供的装置能力描述，含逻辑节点/数据对象/属性，不含实例名与通信参数。 SSD (System Specification Description)：一次系统结构与关联逻辑节点，最终并入 SCD。 SCD (Substation Configuration Description)：全站唯一的系统配置文件，集成所有 IED 模型+通信+变电站描述。 CID (Configured IED Description)：某台 IED 的实例配置(ICD 实例化)，含通信参数，装置最终配置。
3 配置流程
厂家出 ICD → 系统集成商用 SSD + 各 ICD 配置成 SCD → 由 SCD 导出每台装置的 CID/下装。 (第2版新增 IID 实例化 IED、SED 系统交换文件)。
4 SCL 根元素
<SCL xmlns="http://www.iec.ch/61850/2003/SCL" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="...SCL.xsd"> xmlns 定义命名空间，schemaLocation 指明 Schema 位置，可加私有扩展命名空间。
5 五个子元素
SCL 由 5 个子元素构成： 1) Header 文件标识与版本 2) Substation 变电站一次系统结构 3) Communication 通信系统配置 4) IED 智能电子设备模型 5) DataTypeTemplates 数据类型模板 其中 IED 与 DataTypeTemplates 是装置建模核心。
SCL 根与五大子元素
6 Header 元素
标识 SCL 文件：id(唯一标识)、version、revision、toolID(生成工具)、nameStructure(命名结构，IEDName)。 子元素 History/Hitem 记录版本修改历史。
7 Substation 元素
描述一次系统层次： Substation → VoltageLevel(电压等级) → Bay(间隔) → ConductingEquipment(一次设备,如断路器CBR/隔离刀闸DIS)。 各层可含 LNode(引用逻辑节点，把一次设备关联到 IED 的 LN) 与 Function/SubFunction。
8 SubNetwork / ConnectedAP
Communication 含必选子元素 SubNetwork(子网, 如 MMS 站控层网、GOOSE/SV 过程层网)。 SubNetwork → ConnectedAP(连接访问点, 由 iedName+apName 定位某 IED 的通信接入点)。
9 Address 与 P 类型
ConnectedAP 的 Address 用若干 <P> 描述地址： P type="IP"、"IP-SUBNET"、"IP-GATEWAY"(站控层 MMS)、 P type="MAC-Address"、"APPID"、"VLAN-ID"、"VLAN-PRIORITY"(过程层 GOOSE/SV)。
10 GSE 与 SMV
ConnectedAP 下： GSE(对应 GOOSE 控制块通信参数)：含 Address(组播MAC/APPID/VLAN)、MinTime(GOOSE T1 最快重传, 如2ms)、MaxTime(T0 心跳, 如5000ms)。 SMV(对应采样值控制块通信参数)：含 Address(组播MAC/APPID)。 ldInst/cbName 关联到 IED 内的控制块。
11 IED / AccessPoint / Server
IED 属性：name(实例名)、type、manufacturer、configVersion。 IED → AccessPoint(访问点) → Server(服务器) → Authentication(鉴别) + 若干 LDevice。
12 LDevice 与 LN0/LN
LDevice(逻辑设备, 属性 inst 实例号)。 每个 LDevice 必含一个 LLN0(LN0, 逻辑节点零, 承载数据集/控制块/定值组) 和一个 LPHD, 以及若干 LN(逻辑节点)。 LN 属性：lnClass(如 PDIF/PTOC/XCBR/MMXU)、inst、prefix、lnType(引用 LNodeType)。
13 逻辑节点命名
LN 名 = prefix + lnClass + inst，如 Q0XCBR1。 对象引用路径：LDName/LN.DO.DA，如 CL2007ProtCTRL/PTRC1.Tr.general。 逻辑节点按首字母分组(P 保护、M 测量、C 控制、X 开关、T 互感器、G 通用 GGIO 等)。
14 DataSet / FCDA
DataSet(数据集, 定义于 LN0/LN)：一组数据的集合，报告/GOOSE/SV 引用它上送。 成员 FCDA 用 ldInst/prefix/lnClass/lnInst/doName/daName/fc 定位一个数据(功能约束数据属性)。
15 ReportControl(报告控制块)
缓存报告 BRCB 与非缓存报告 URCB。 属性：name、datSet(引用数据集)、rptID、confRev、buffered、intgPd(周期)、 TrgOps(触发条件: dchg 数据变化/qchg 品质变化/dupd 更新/period 周期/gi 总召)、 OptFlds(任选域: 序号/时标/原因/数据集名/数据路径/缓冲溢出/条目号/配置号)。
16 LogControl / GSEControl / SVControl
LogControl：日志控制块(记录到日志)。 GSEControl：GOOSE 控制块(type=GOOSE/GSSE)，属性 appID、datSet、confRev。 SampledValueControl：采样值控制块(SMV)，属性 smvID、datSet、smpRate、nofASDU、confRev。 SettingControl：定值组控制块，属性 numOfSGs(定值区数)、actSG(当前运行区)。
17 DOI / SDI / DAI
在 LN 内对数据对象/属性赋实例值： DOI(数据对象实例, name=DO 名) → SDI(子数据实例, 结构嵌套) → DAI(数据属性实例) → Val(具体值)。 如给 ctlModel、定值、描述等赋值。
18 Inputs / ExtRef(虚端子)
Inputs 描述本 LN 订阅的外部信号(GOOSE/SV 接收)。 ExtRef 用 iedName/ldInst/lnClass/doName/daName 指向源信号(发布方)。 SCD 中的 ExtRef 连线即“虚端子”，是过程层 GOOSE/SV 联系的配置核心。
19 四类模板
DataTypeTemplates 含： LNodeType(逻辑节点类型, 必选)、DOType(数据对象类型, 必选)、DAType(数据属性类型)、EnumType(枚举类型)。 LN 的 lnType 引用 LNodeType，逐层引用形成完整类型定义。
20 LNodeType / DOType
LNodeType：属性 id、lnClass；子元素 DO(数据对象, name+type 引用 DOType)。 DOType：属性 id、cdc(公共数据类, 如 SPS/DPS/MV/ACT/SPC…, 见 IEC 61850-7-3)； 子元素 SDO(子数据对象)、DA(数据属性)。
21 DAType / EnumType
DAType：结构化数据属性类型，子元素 BDA(基础数据属性)。 EnumType：枚举类型，子元素 EnumVal(ord+文本)。 DA/BDA 属性：name、bType(基本类型: BOOLEAN/INT32/FLOAT32/Enum/Struct/Timestamp/Quality…)、fc(功能约束)、type。
22 公共数据类 CDC 与 FC
CDC(Common Data Class)规定 DO 的结构，如 SPS 单点状态、DPS 双点、MV 测量值、SPC 单点控制、ACT 保护动作。 FC(功能约束)标记 DA 用途：ST 状态、MX 测量、CO 控制、SP 定值(运行区)、SE 定值(编辑区)、SG 定值组、DC 描述、CF 配置、EX 扩展。
